# Core idea

Terminal agents fail in recurring ways:

* they edit before reading the stack trace,
* they rerun the full test suite instead of the failing test,
* they ignore CLI error messages,
* they do not inspect config files,
* they break working behavior while fixing one case,
* they blindly upgrade dependencies,
* they fail to use `git diff`, `grep`, logs, or minimal repros.

Most systems just retry or add a generic prompt.

Terminal DreamGym does something more recursive:

```text
agent attempts terminal task
→ agent fails
→ Gemini diagnoses missing capability
→ DreamGym generates targeted practice terminal worlds
→ agent learns/evaluates recovery skills on those worlds
→ robust skills are promoted only if they transfer
→ agent retries original and held-out tasks
```

The “dream” is the generated practice environment.

Core pitch:

> When a terminal agent fails, Terminal DreamGym creates small practice repos/shell tasks that isolate the missing capability, teaches the agent recovery skills, and only promotes skills that generalize to held-out terminal tasks.

This is not a generic coding assistant.

This is a **self-improvement harness for terminal agents**.

# Research claim

Research question:

> Can agents improve more reliably if they generate targeted practice environments from their own terminal failures, instead of only reflecting or retrying?

Hypothesis:

> Failure-conditioned curriculum generation produces more transferable terminal skills than naive reflection alone.

The project compares:

1. **Baseline agent**

   * Attempts original terminal tasks with no generated skills.

2. **Reflection-only agent**

   * Writes a skill from the failure and retries the original task.

3. **Terminal DreamGym agent**

   * Diagnoses the failure, generates practice terminal worlds, evaluates skills on those worlds, then tests on held-out/adversarial terminal tasks before promotion.

The demo should show:

```text
Baseline:
fails original / held-out terminal tasks

Reflection-only:
improves on original but overfits

Terminal DreamGym:
generates practice worlds
learns transferable skill
improves held-out/adversarial tasks
```

# Terminal task domains

Create local toy-but-realistic terminal tasks.

At least 4 original task families:

## 1. Python failing test repair

Task:
A Python function fails tests because of an edge case.

Example:

* `normalize_email(email)` crashes on whitespace or uppercase input.
* `parse_price("$1,234.50")` fails on commas.
* `slugify("Hello, World!")` leaves punctuation.

Expected correct behavior is encoded in pytest tests.

## 2. CLI edge-case repair

Task:
A CLI tool crashes or returns wrong output on edge cases.

Example:

* `python cli.py --input ""` crashes.
* Missing file gives bad error.
* `--json` flag returns invalid JSON.

## 3. Config/env failure

Task:
Tests fail because app reads the wrong config key or does not handle missing env vars.

Example:

* config changed `api_key` to `auth.token`.
* app expects `TIMEOUT` but config uses `request_timeout`.

## 4. Dependency/API mismatch

Task:
A local module changed function signature.

Example:

* old helper: `format_user(name, email)`
* new helper: `format_user(user: dict)`
* app still calls old interface.

All tasks must be local and deterministic.

# Mock terminal agent

Implement `mock_agent.py`.

The mock agent should simulate terminal-agent behavior deterministically.

Strategies:

## `baseline`

Brittle:

* runs full pytest once,
* applies a simplistic patch based on task family,
* may ignore stack trace,
* may over-edit,
* succeeds only on simple train tasks.

## `reflection_only`

Improves on the exact failure but overfits:

* learns a narrow or overbroad heuristic from the observed failure,
* improves train score,
* causes held-out/adversarial regressions.

Examples:

* removes commas globally,
* defaults all missing env vars,
* catches all exceptions and returns empty string,
* pins dependency by editing code in brittle way.

## `dreamgym_skill`

Robust:

* runs the smallest failing test first,
* reads traceback,
* inspects relevant function/config,
* makes minimal patch,
* adds or preserves regression tests,
* avoids overbroad fixes,
* reruns targeted test then full suite.

## `trace_first_skill`

Skill:

* inspect failure trace before editing.

## `minimal_patch_skill`

Skill:

* fix only the failing boundary condition.

## `contract_check_skill`

Skill:

* compare expected vs actual interface/config/schema.

The mock agent must make actual file edits in task sandboxes.

This means the demo produces real diffs and real passing/failing tests.

# Skill generation

Implement `skill_generator.py`.

Generate `SKILL.md` files from diagnoses and curricula.

Required generated skills:

## `trace_first_debugging_skill.md`

```md
# Skill: Trace-first terminal debugging

When a terminal task fails:
1. Re-run the exact failing command.
2. Read the traceback or error output before editing files.
3. Identify the smallest failing test or command.
4. Inspect the referenced function, config key, or interface.
5. Make the smallest patch that addresses the observed failure.
6. Rerun the targeted test first, then the full suite.
```

## `minimal_patch_skill.md`

```md
# Skill: Make minimal behavior-preserving patches

When fixing a bug:
1. Preserve existing behavior unless the task explicitly says otherwise.
2. Add or check counterexamples before applying broad transformations.
3. Avoid global string rewrites, blanket exception handlers, or default values that hide required errors.
4. Patch the narrowest function or adapter responsible for the failure.
5. Verify both the original failure and nearby edge cases.
```

## `contract_drift_skill.md`

```md
# Skill: Repair contract drift

When code fails after an interface, config, or schema change:
1. Compare the expected contract to the observed contract.
2. Identify renamed, nested, removed, or type-changed fields.
3. Patch the adapter/client/config normalization layer before changing business logic.
4. Add a regression test for the new contract.
5. Preserve backwards compatibility when possible.
```

## `error_handling_skill.md`

```md
# Skill: Handle errors without hiding failures

When a task involves invalid input or missing configuration:
1. Distinguish optional missing values from required missing values.
2. Return clear validation errors for bad user input.
3. Do not catch all exceptions unless the task explicitly requires it.
4. Do not silently default required secrets, credentials, or critical config.
5. Add tests for both valid and invalid paths.
```

Also generate one intentionally brittle skill:

## `reflection_overfit_skill.md`

```md
# Skill: Patch the last visible symptom

When a terminal task fails, apply the simplest transformation that makes the observed error disappear, even if it is broad.

Examples:
- Remove problematic characters globally.
- Add default values for missing variables.
- Catch exceptions and return empty output.
- Upgrade or pin dependencies without checking the contract.

This skill may improve the observed training case but can overfit and cause regressions.
```

The brittle skill must improve some train cases but cause held-out/adversarial regressions.

# Promotion logic

Implement `promotion.py`.

```python
def naive_promote(train_delta: float) -> bool:
    return train_delta > 0
```

```python
def promote_skill(
    train_delta: float,
    heldout_delta: float,
    adversarial_delta: float,
    adversarial_regressions: int,
    practice_score: float,
    min_heldout_delta: float = 0.01,
    min_practice_score: float = 0.70,
    max_adversarial_regressions: int = 0,
) -> bool:
    return (
        train_delta >= 0
        and heldout_delta >= min_heldout_delta
        and adversarial_delta >= 0
        and adversarial_regressions <= max_adversarial_regressions
        and practice_score >= min_practice_score
    )
```

Report must show:

* naive reflection would promote brittle skill,
* Terminal DreamGym rejects it,
* Terminal DreamGym promotes robust skill.

# Acceptance criteria

These commands must work:

```bash
pip install -e ".[dev]"
python -m terminal_dreamgym.cli demo
pytest -q
```

The demo must generate:

```text
runs/baseline.json
runs/diagnoses.json
curricula/generated/*.json
skills/generated/*.md
runs/evaluation.json
reports/report.md
reports/report.html
```

The report must clearly show:

1. Baseline terminal-agent brittleness.
2. Failure diagnosis.
3. Generated practice terminal worlds.
4. Generated skills.
5. Reflection-only overfitting.
6. Terminal DreamGym transfer-gated improvement.
7. Gemini 3.5 managed-agent / terminal-agent integration path.
8. Hackathon theme fit.
9. Statement that this is not a banned project.
